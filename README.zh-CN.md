# LLM Output Clarity：受 Karpathy 启发的 Agent Skill

**读懂结论，看清依据，知道下一步。**

[English](./README.md) | [简体中文](./README.zh-CN.md) | [日本語](./README.ja.md) | [Español](./README.es.md) | [العربية](./README.ar.md)

[安装说明](./docs/installation.md) | [设计取舍](./docs/design.md) | [评测方法](./evals/README.md)

这个 Skill 帮助 Agent 把复杂输出转换为清晰文字、图解、交互 HTML 或解释视频。
不是一味缩短回答，而是降低理解成本，同时保留事实、条件、风险和不确定性。

灵感来自 [Karpathy 在 2026 年 10 月 2 日的原帖](https://x.com/karpathy/status/2105819303471976479)：
AI 承担更多工作后，人需要更好地理解和检查结果。
原帖建议用接近 ASD-STE100 的文字、图像、交互网页和定制视频帮助理解。

本项目与 Karpathy 或 ASD 没有隶属或背书关系，不是 STE 合规认证工具，也不是事实校验器。

## 按问题选择表达形式

| 形式 | 适用场景 | 本项目提供什么 |
| --- | --- | --- |
| 清晰文字 | 问题分析、解释、行动建议 | 结论优先，保留证据和不确定性 |
| 图解和图片 | 调用链、分支、状态或空间关系 | 选择图类型，标注推测关系，提供文字替代 |
| 交互 HTML | 比较状态、改变参数、展开大量证据 | 离线、可访问的页面生成指导 |
| 解释视频 | 用动态过程帮助学习 | 脚本、分镜、预览、配音和检查流程 |

简单问题不强制画图。HTML 和视频需要用户请求或同意。
这个 Skill 不自带浏览器、视频渲染器、语音模型或付费 API。

## 一个合成示例

输入：20 个请求中有 3 个返回 429；网关和下游均可能限流；响应头未知。

不可靠的简化：

> 根因是网关配额不足，增加并发即可解决。

期望的输出：

> 暂不建议增加并发，先确认限流来源。
>
> 已知 3 个请求返回 429，但现有信息不能区分网关和下游限流。
> 下一步检查失败请求的响应头及对应日志，再决定配额或并发调整。

这是人工编写的目标示例，不是模型效果测试结果。

规则还要求保留“谁提出了这个说法”，并在新证据出现时修正判断。
“只返回 JSON”等严格格式优先；代码评审仍按问题严重程度组织，不套用统一模板。

## 通用安装

直接从 GitHub 仓库安装：

```sh
npx skills add stoneboy100200/llm-output-clarity --skill llm-output-clarity --global --copy
```

这是同一套标准 Agent Skills 文件，不是 Copilot 专用版本。
Skills CLI 可面向 Claude Code、Codex、Cursor、Gemini CLI、OpenCode、GitHub Copilot
及其他支持的工具安装。安装器会检测工具，并在需要时让你选择；确认安装摘要中的目标。
无人值守安装请显式指定 `--agent`，不要依赖自动检测；不要用 `--all` 代替目标选择。

安装器需要 Node.js 和网络；使用 Skill 本身无需安装项目开发依赖。
也可以按[安装说明](./docs/installation.md)离线复制整个 Skill 文件夹。
外部 Skills 安装器可能发送安装遥测，关闭方式见安装说明；本 Skill 自身没有遥测。

只安装到指定工具时，可以追加标识，也可以指定多个。例如：

```sh
npx skills add stoneboy100200/llm-output-clarity --skill llm-output-clarity --global --copy --agent claude-code codex
```

其他标识、手动安装路径和检查方式见[安装说明](./docs/installation.md)。
安装器支持这些工具，不代表本项目已完成所有平台的行为测试。

源仓库为 [stoneboy100200/llm-output-clarity](https://github.com/stoneboy100200/llm-output-clarity)。
要安装已检查的本地副本，可在项目根目录执行命令，并将仓库标识替换为 `.`。
本项目没有发布 npm 包。

## 使用方式

安装后，可以直接在对话中点名使用，不依赖某个平台的命令前缀：

```text
请使用 llm-output-clarity 分析这个问题，先给结论，再给依据和下一步。
请使用 llm-output-clarity 用图说明请求如何跨服务传递，标出尚未证实的环节。
请使用 llm-output-clarity 生成离线 HTML，用切换按钮比较修改前后。
请使用 llm-output-clarity 设计解释视频的分镜，先不要安装软件。
```

需要显式调用时：Claude Code 用 `/llm-output-clarity`，Codex 用
`$llm-output-clarity`，Copilot 用 `/llm-output-clarity`；其他工具按其 Skill 菜单使用。
自然语言请求仍需要宿主已加载这个 Skill；普通模型 API 不会自动读取本机文件。

支持自动选择 Skill 的宿主可以按任务相关性加载，但不能保证每次触发。
默认只作用于当前请求。说“本会话持续使用这个 Skill”可请求会话模式。
说“停止 clarity 模式”后，规则要求 Agent 在本会话不再自动启用，直到你再次要求。
新会话按宿主规则重新选择；没有持久化的开关。上下文压缩可能削弱遵循效果，
这些是指令约定，不是程序强制机制。安装不会修改常驻指令或其他 Skill。

## 多语言支持的边界

**不只适合五种语言。** 指令用英文编写，回答跟随用户请求，不设置语言白名单。
例如可以请求法语、德语或葡萄牙语；实际质量取决于所用模型，尚未逐一验证。
中文采用短句、明确指代和一致术语，
不机械套用英语词数或时态规则。项目包含中、英、西、日、阿拉伯语的合成用例。

**有用例不等于语言质量已经验证。** 尚未完成跨模型盲评或母语使用者评审。
工具测试通过也不能证明答案一定正确，详见[验证状态](./docs/validation.md)。

项目提供英、简中、日、西、阿拉伯语五种 README，翻译尚待熟练使用者人工复核。
英文版是维护基准；链接指向的高级文档目前仍为英文。
README 翻译覆盖与模型实际语言能力是两回事。

## 为什么不默认严格 STE

严格 ASD-STE100 是英语技术文档规范，包含写作规则、受控词典及行业术语要求。
它有助于减少歧义，但不保证事实或诊断正确，也不能直接当作中文或其他语言的规范。
Karpathy 在原帖中也提到，规范较严格，因此有时采用接近“80%”的宽松写法。
这里的“80%”是表达偏好，不是可测量的合规分数。

默认保留这些清晰表达原则，同时优先保留条件、例外和不确定性。
英文操作文档可以明确请求更严格的 STE 写法；但不能仅凭模型记忆声明完全合规。
正式合规任务需要按适用版本的规范、词典和项目术语表逐项审查。
本项目不附带 ASD 标准或词典，也不提供严格合规认证模式。

## 相比参考项目的设计取舍

- 保留 STE 的清晰表达原则，不声称完整符合标准。
- 区分改写、摘要、分析与建议；允许推理，但不得把假设冒充事实。
- 不强制固定标题、五条上限或重复进度；复杂任务仍保留必要细节。
- 保留原帖的视频路线，但按需使用，不自动安装或调用服务。
- 提供对照评测工具；没有证据时不宣称“比原版更好”。
