# LLM Output Clarity：Karpathy の提案に着想を得た Agent Skill

**結論を理解し、根拠を確認し、次の行動を判断する。**

[English](./README.md) | [简体中文](./README.zh-CN.md) | [日本語](./README.ja.md) | [Español](./README.es.md) | [العربية](./README.ar.md)

[インストール](./docs/installation.md) | [設計](./docs/design.md) | [評価方法](./evals/README.md)

この Skill は、複雑な AI の出力を、明確な文章、図解、対話型 HTML、解説動画に整理します。
単に短くするのではなく、事実、条件、根拠、不確実性を保ったまま理解の負担を減らします。

着想は [Andrej Karpathy による 2026 年 10 月 2 日の投稿](https://x.com/karpathy/status/2105819303471976479)です。
AI が多くの作業を担うほど、人は結果を理解し、確認する必要があります。
投稿では ASD-STE100 に近い文章、図や画像、対話型ページ、個別の解説動画を提案しています。

本プロジェクトは独立したもので、Karpathy や ASD との提携・承認関係はありません。
ASD-STE100 の適合性を認証するツールでも、事実確認ツールでもありません。

## 内容に合う形式を選ぶ

| 形式 | 適した場面 | 提供するもの |
| --- | --- | --- |
| 明確な文章 | 結論、説明、対応案 | 読みやすい表現と根拠を保つ規則 |
| 図解・画像 | 関係、分岐、時系列、空間構造 | 図の選択、仮説の表示、文章による代替 |
| 対話型 HTML | 状態の比較、値の変更、詳細の確認 | オフライン優先で利用しやすいページの作成手順 |
| 解説動画 | 動きや音声が理解を助ける場合 | 台本、絵コンテ、描画、検証の手順 |

簡単な質問に図は必須ではありません。HTML と動画には明示的な依頼か合意が必要です。
ブラウザー、動画レンダラー、音声モデル、有料サービスは同梱・自動インストールしません。

## 架空の例

入力：20 件のリクエストのうち 3 件が HTTP 429 を返した。
ゲートウェイと下流サービスの両方が制限を行う可能性があり、応答ヘッダーは不明。

不適切な要約：「ゲートウェイのクォータ不足です。同時実行数を増やしてください。」

より明確な回答：

> 同時実行数を増やす前に、制限を返したサービスを確認してください。
> 3 件が 429 を返しましたが、制限元はまだ不明です。
> 失敗したリクエストの応答ヘッダーと対応するログを確認してから、変更を判断します。

これは目標を示す作成例であり、モデルの実測結果ではありません。
規則は情報源の区別、新しい証拠に基づく結論の更新、JSON のみなどの厳密な形式も扱います。
コードレビューでは重要度の高い指摘を先に示し、すべての回答に同じテンプレートを強制しません。

## インストール

GitHub リポジトリから直接インストールします。

```sh
npx skills add stoneboy100200/llm-output-clarity --skill llm-output-clarity --global --copy
```

同じ標準 Agent Skills ファイルを Claude Code、Codex、Cursor、Gemini CLI、OpenCode、
GitHub Copilot などにインストールできます。Skills CLI がツールを検出し、必要に応じて選択を求めます。
確認画面で対象を確認してください。無人実行では `--agent` を明示し、`--all` を選択の代わりに使わないでください。
外部の Skills CLI には Node.js、ネットワーク、書き込み権限が必要です。
Skill 自体の利用に開発用の `npm install` は不要です。
インストーラーのテレメトリ停止やオフラインでのフォルダーコピーは[インストールガイド](./docs/installation.md)を参照してください。
この Skill 自体はテレメトリを送信しません。

対象を限定する場合は、識別子を一つ以上指定します。例：

```sh
npx skills add stoneboy100200/llm-output-clarity --skill llm-output-clarity --global --copy --agent claude-code codex
```

ほかの識別子と手動配置先はインストールガイドを参照してください。
インストーラーの対応は、各ホストで動作を検証済みという意味ではありません。

ソースは [stoneboy100200/llm-output-clarity](https://github.com/stoneboy100200/llm-output-clarity) です。
確認済みのローカル版を使う場合は、リポジトリ名を `.` に置き換え、そのルートで実行します。
本プロジェクトは npm パッケージを公開していません。

## 使い方

インストール後、チャットで Skill 名を指定します。共通の依頼文ならコマンド接頭辞に依存しません。

```text
llm-output-clarity を使い、この障害を日本語で説明し、確認済みの事実と仮説を分けてください。
llm-output-clarity を使い、リクエストの流れを図にしてください。未確認の関係を明示してください。
llm-output-clarity を使い、変更前後を切り替えられるオフライン HTML を作ってください。
llm-output-clarity を使い、解説動画の絵コンテを作ってください。まだソフトウェアはインストールしないでください。
```

直接呼び出す場合、Claude Code は `/llm-output-clarity`、Codex は `$llm-output-clarity`、
Copilot は `/llm-output-clarity` を使います。ほかのツールでは対応する Skill メニューを確認してください。
ホスト側で Skill の読み込みが必要です。通常のモデル API はローカルファイルを自動検出しません。
対応ホストでは関連する依頼から自動選択される場合がありますが、毎回の起動は保証されません。

既定では現在の依頼に適用します。「このセッションの間、この Skill を使ってください」で継続を依頼できます。
「Stop clarity mode」と伝えた後は、再度依頼するまで同じ会話で自動再開しないよう指示されています。
新しい会話ではホストの選択規則に従い、永続的なオン・オフ状態は保存しません。
コンテキストの圧縮で遵守が弱まることがあります。これは指示であり、プログラムによる強制ではありません。
インストールしても常時適用ルールや他の Skill は変更しません。

## 確認・更新・削除

```sh
npx skills list --global
```

利用するツールの Skill 一覧や設定でも確認し、必要に応じて再読み込みか新規会話を行います。
インストール記録はホストによる読み込みを証明せず、一覧への表示も動作の正しさを証明しません。
原因不明の小さな課題で回答も確認してください。個別の手順はインストールガイドにあります。

ローカル版の更新は、ソースの変更を確認してからインストールコマンドを再実行します。
上書き前に独自の変更を退避してください。リモート版の更新はインストールガイドを参照してください。

Skills CLI で管理するユーザーインストールの削除：

```sh
npx skills remove llm-output-clarity --global
```

`--agent` を省略すると、複数のホストから同名 Skill が削除される場合があります。
一つのツールだけを対象にする場合は `--agent` を指定し、削除範囲を確認してください。

手動コピーの場合はこの Skill のフォルダーだけを削除します。
別途追加した常時適用ルールは個別に削除し、新しいチャットを開始してください。

## 言語と制限

**出力は五つの言語に限定されません。** 指示は英語ですが、回答はユーザーが指定した言語に従います。
言語の許可リストはありません。フランス語、ドイツ語、ポルトガル語なども依頼できますが、
品質はモデルの能力に依存し、ここでは未検証です。
英語の単語数や時制の規則を、ほかの言語に機械的に適用しません。
英語、中国語、スペイン語、日本語、アラビア語の架空の評価課題があります。

- 課題や翻訳があることは、言語品質が検証済みであることを意味しません。
- この README を含む翻訳は初稿です。言語に堪能な人による確認は未実施です。英語版を保守の基準とし、リンク先の詳細ガイドは現在英語です。
- 分かりやすい表現だけでは、診断の正しさは証明できません。
- HTML・動画にはホスト側のツールが必要です。ここに含まれるのは作成・確認手順です。
- モデル間の比較や優位性は未検証です。[検証状況](./docs/validation.md)を確認してください。競合する常時適用スタイルの併用は避けてください。

## 厳密な STE を既定にしない理由

ASD-STE100 は、執筆規則、管理語彙辞書、分野の用語を用いる英語の技術文書規格です。
曖昧さの削減には役立ちますが、事実や診断の正しさを証明するものではなく、ほかの言語の文法規則でもありません。
Karpathy 自身も、厳しさを和らげるために「80% 程度」の書き方を使うことがあると述べています。
これは表現上の目安であり、適合性の得点ではありません。

既定では明確さの原則を借りつつ、条件、例外、不確実性を保ちます。
英語の手順書には、より厳密な STE 風の文体を依頼できます。ただしモデルの記憶だけで完全な適合を主張しません。
正式な用途では、該当する規格、辞書、プロジェクト用語集との照合が必要です。
本プロジェクトは ASD の規格や辞書、厳密な適合認証モードを提供しません。

## 開発と評価

開発用には Node.js 22 以降と npm が必要です。Skill の利用自体には不要です。

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run eval:validate
```

評価ツールはローカルで比較用入力と条件名を隠したレビュー資料を作り、採点結果を集計します。
モデルを呼び出したり、データを送信したり、API 料金を使ったりしません。[評価手順](./evals/README.md)を参照してください。
